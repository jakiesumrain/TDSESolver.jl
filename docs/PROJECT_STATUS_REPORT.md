## 1. UNSOLVED PROBLEMS (Current Status)

### Critical Issues (Block Production Use)

#### Problem #1: S-Matrix Non-Unitarity ⚠️ HIGH PRIORITY

**Status:** UNSOLVED

**Description:**
- S-matrix causes 8% norm loss per application (1.0 → 0.924)
- Two applications per time step compound to ~15% loss
- Results in exponential norm divergence over many steps

**Root Cause:**
Inaccurate numerical eigenstates (Problem #2) → Non-orthonormal basis → Non-unitary S-matrix

**Formula:**
```
S_{ij}(l) = Σₙ φₙ(xᵢ) φₙ(xⱼ) exp(-iEₙΔt/2) wⱼ
```
When φₙ are inaccurate (especially l=0), orthonormality fails.

**Impact:**
- ✅ LOW for coordinate transformation testing (can skip S-matrix)
- ❌ HIGH for full simulations (norm diverges exponentially)
- ❌ CRITICAL for production physics results

**Possible Solutions:**
1. Fix eigenstate solver (addresses root cause - see #2)
2. Force Gram-Schmidt orthonormalization
3. Symmetrize S-matrix numerically (enforce S†S = I)
4. Use pre-computed eigenstates (Fortran approach!)
5. Alternative propagators (Crank-Nicolson, exponential integrators)

**Workaround (Current):**
Use analytical ground states instead of numerical eigenstates

**Files:**
- `src/propagator/Propagator.jl` - apply_s_matrix!()
- `tests/test_transformation_debug.jl` - Test 3 documents issue

#### Problem #2: Eigenstate Solver Accuracy ⚠️ HIGH PRIORITY

**Status:** UNSOLVED - Workaround in place

**Description:**
Runtime eigenstate solver produces ground state energies ~50x too negative:
- H: E₁ₛ ≈ -26 Ha (should be -0.5 Ha)
- He: E₁ₛ ≈ -83 Ha (should be -0.9 Ha)
- Higher l states (l≥1) show correct behavior

**Root Cause:**
Finite difference discretization on highly non-uniform GPS grid produces numerical errors for l=0 states

**Key Insight from Fortran:**
⚠️ **CRITICAL DISCOVERY:** The Fortran programs do NOT compute eigenstates at runtime!

From `explore/CLAUDE.md` lines 138-148:
```
Critical prerequisite: Pre-computed eigenstate data must exist
Files: e-value_r200.lmax99.txt, e-vector_l99_0.9010.bin
Generated by: Separate programs using quad precision (real*16)
Method: GPS spectral derivative methods (NOT finite differences)
```

**This means:**
The Fortran implementation uses **offline high-precision eigenstate generation**, not runtime calculation!

**Current Workaround:**
Using analytical ground state wavefunctions:
- H: ψ₁ₛ(r) = 2 exp(-r) / √(4π) [exact]
- He: Effective Z approach [very good approximation]
- See: `src/hamiltonian/AnalyticalStates.jl`

**Impact:**
- ✅ LOW for MVP (analytical states sufficient)
- ⚠️ MEDIUM for production (need excited states)
- ❌ HIGH for quantitative results (need accurate initial states)

**Possible Solutions:**
1. **Pre-computation approach** (matches Fortran!) - Generate eigenstate database offline
2. GPS spectral derivatives (complex to implement)
3. Quad precision arithmetic (Julia supports BigFloat)
4. External eigensolver (PETSc/SLEPc interface)
5. Shooting method (traditional QM approach)

**Files:**
- `src/hamiltonian/Hamiltonian.jl` - construct_kinetic_matrix()
- `src/hamiltonian/AnalyticalStates.jl` - Workaround implementation
- `tests/unit/test_hamiltonian.jl` - Documents ~50x error

#### 2.3 S-Matrix Construction (GOOD)
**File:** `src/propagator/Propagator.jl`

**Fortran Reference:** Lines 255-293

**Fidelity:** ✅ **GOOD** (Correct algorithm, some simplifications)

**Julia Implementation:**
```julia
function construct_s_matrix(ham, l, dt; energy_cutoff=50.0)
    nrmax = length(ham.grid.radial_grid)
    S = zeros(ComplexF64, nrmax, nrmax)

    for n in 1:ham.n_states[l+1]
        E_n = ham.eigenvalues[n, l+1]
        if E_n < energy_cutoff
            phase = exp(-im * E_n * dt / 2.0)
            for i in 1:nrmax
                for j in 1:nrmax
                    S[i,j] += ham.eigenvectors[i,n,l+1] *
                             ham.eigenvectors[j,n,l+1] *
                             phase * weights[j]
                end
            end
        end
    end
    return S
end
```

**Matches Fortran:**
- Energy cutoff threshold
- Phase factor exp(-iEΔt/2)
- Weight pre-multiplication
- Summation over bound states only

**Differences:**
- Julia uses modern array syntax
- No explicit symmetrization (S[i,j] = S[j,i] for i>j)
- ⚠️ Uses inaccurate numerical eigenstates (Problem #2)

**Status:** Algorithm correct, but input data (eigenstates) inaccurate
